Dataset 1 of 2

UCSD Resting-State EEG

ds002778

Parkinson's disease patients and healthy controls, recorded at UC San Diego, curated onto OpenNeuro by Alex Rockhill (University of Oregon). License: CC0. DOI: 10.18112/openneuro.ds002778.v1.0.4.

ColumnMeaning

In practice: for the resting task, this file is nearly empty — one subject's real file contains exactly two rows (a recording-start marker and a single trigger). This is a technical log, not a record of task events. Don't expect rich annotations here the way a task-based study would have them.

eeg.json (recording sidecar)

Real values from sub-hc1's sidecar: TaskName: "rest", Manufacturer: "Biosemi", PowerLineFrequency: 60, SamplingFrequency: 512.0, EEGChannelCount: 40, RecordingDuration: ~192s. EEGReference and EEGGround are both "n/a" — the montage detail simply wasn't documented.

What the README adds that the tables don't

  • UPDRS (Parkinson's severity) ratings were collected by trained lab staff, not a board-certified neurologist — the README explicitly asks that analyses built on them carry appropriate uncertainty. Also: no UPDRS scores actually appear in participants.tsv or any phenotype file at the top level — despite being mentioned, they weren't found in the structured data.
  • Curators ask to be emailed (arockhil@uoregon.edu) before any manuscript is submitted using this data, and list three specific papers they want cited.
  • The README explicitly warns against reporting high classification accuracy (e.g. Parkinson's vs. healthy) without cross-validation, calling that use "problematic."

Mental Arithmetic Tasks

eegmat

Healthy volunteers performing serial subtraction, recorded at Taras Shevchenko National University of Kyiv by Igor Zyma, Sergii Tukaev, and Ivan Seleznov. License: Open Data Commons Attribution v1.0 — permissive, but requires attribution (unlike ds002778's CC0).

File naming

Subject##_1.edf is the background/baseline recording; Subject##_2.edf is the same subject during the arithmetic task — 36 subjects × 2 files = 72 EDF files. There is no channels.tsv equivalent: channel names exist only inside each EDF file's own header, not as a separate declared sidecar the way ds002778 provides.

Recording setup

Neurocom 23-channel monopolar system (XAI-MEDICA, Ukraine), electrodes placed per the 10–20 system, all referenced to interconnected ear electrodes. A 50 Hz notch filter removed power-line noise.

Worth verifying before writing parsing code

The dataset's own README states a "high-pass filter with a 30 Hz cut-off" was applied. A high-pass at 30 Hz would remove nearly everything below it — delta, theta, alpha, and most of beta — which would be unusual for a study explicitly measuring cognitive workload, where those bands normally matter most. An independent summary of the same dataset's original data-descriptor paper instead describes a 0.5–60 Hz band-pass. The two don't agree, and I haven't resolved which is correct.

Don't hardcode either number into transformation logic — read the actual passband out of the EDF header at parse time instead of trusting either document.

Who's in the cohort

Eligibility required normal or corrected vision, normal color vision, and no diagnosed cognitive or learning impairment. Excluded: psychoactive medication use, drug or alcohol dependency, and psychiatric or neurological complaints — so unlike ds002778, this is an all-healthy comparison cohort split only by task performance, not diagnosis.

The gotchas

Things to remember

Everything below is something a first pass through the documentation alone would likely miss.

  • ds002778

    events.tsv is essentially empty for the resting task — two technical marker rows, not annotated task events. Don't design transformation logic around it having real content.

  • ds002778

    The beh/ folder and its task-rest_beh.json sidecar are a BIDS-required placeholder — the sidecar literally says "there are no trials, this is just a dummy column." Ignore it rather than trying to parse real behavioral data out of it.

  • both

    Sampling rates differ — 512 Hz vs. 500 Hz. Any statistic compared across the two datasets (e.g. recording duration, event timing) has to be computed in seconds, never in raw sample counts, or the comparison is silently wrong.

  • both

    Channel-naming conventions differ. ds002778's 40-channel BioSemi cap uses extended 10–20 names (AF3, FC1, FC5, CP1, CP5, PO3, PO4 and similar) that eegmat's 23-channel layout doesn't have. Reconciling channel names across the two sources is real transformation work, not a formality — exactly the kind of standardization problem described in PROJECT_PLAN.md §1.

  • eegmat

    No per-recording channels.tsv exists. Channel names have to come from parsing the EDF header itself, which also means there's no separate "declared vs. actual" cross-check the way ds002778 effectively offers.

  • eegmat

    The documented filter passband is inconsistent across sources (see the flagged note in the eegmat section above) — verify against the raw EDF header rather than trusting either number.

  • ds002778

    Licensed CC0 (no attribution required) but the curators still ask to be emailed before any publication using the data. Not a legal requirement, but worth honoring in any acknowledgements this project writes.

  • both

    Licenses are both permissive but not identical: CC0 (ds002778) waives essentially all rights, while ODC-BY 1.0 (eegmat) requires attribution. Any "how to cite this data" note in the project needs to handle them differently.
